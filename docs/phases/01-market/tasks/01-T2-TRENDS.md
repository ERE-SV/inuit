## Content of T2 (this is the whole assignment)

You produce **six theme cards** in one table, then one **if-wrong + do-not-claim** note.

Every card uses the **same fields**. Facts come from T1 by path. If T1 has no fact, the card is still required: write `unknown` and a so-what that starts with “If we later learn ….”

### The six themes (required — do not swap for a random seventh)

| ID | Theme | Typical T1 paths | Product question the card must answer |
| --- | --- | --- | --- |
| **T2-A** | Labour-market motion | Q6, Q11 | Does CH hiring volume / growth / seasonality change *when* or *where* a matchmaking wedge can get liquidity? |
| **T2-B** | Seeker apply load and AI letters | Q14, Q15, Q16 | Does endless applying / cover-letter noise justify a **reusable profile** and **no letter factory**? |
| **T2-C** | Employer inbound noise and time-to-hire | Q5, Q8, Q9, Q15 | Does screening flood / slow hire justify **Top-X pre-qualified** intros instead of another listing? |
| **T2-D** | Structured / skills-based requirements | Q18, Q20 | Does matching need **structured must-haves** both ways, not keyword search on ad text? |
| **T2-E** | Salary transparency | Q14, Q20, brief hypothesis | Can the product use **company ranges** and **seeker floors** as hard filters, or is that still `unknown`? |
| **T2-F** | Preference fit (commute, place, culture, remote) | Q12, Q14, Q15, vision | Which seeker/company preferences must be **first-class match fields** (especially commute)? |

No extra themes. If T1-Q20 has a seventh trend you love, fold it into the closest card or park it in a footnote — do not add a seventh row.

### Fields on every card

| Field | What to write |
| --- | --- |
| **Fact** | One checkable sentence + T1 path (or new URL + date if T1 was empty). Not the brief’s 40–50 / 2–3k unless T1 sourced them. |
| **Strength** | `strong` (Tier A/B, CH, recent) · `weak` (anecdote, foreign, dated, apply-log only) · `unknown` (searched, nothing usable) |
| **So what — seekers** | One sentence: what we would change for the seeker job. |
| **So what — companies** | One sentence: what we would change for the employer job. |
| **So what — product** | One sentence: a **concrete** matching / profile / notify implication (a field, a rule, or a non-goal). |
| **Must not claim yet** | One sentence: messaging or design we **forbid** until evidence is stronger. |

**If-wrong** (Q7 only): pick the **one** card that would most change MVP if the fact is reversed. Say what we would drop or delay.

### What a so-what is not

| Weak (fail) | Strong |
| --- | --- |
| “This matters for HR.” | “Seekers need a commute hard-filter; listings that only have a city name cannot satisfy it without workplace + transit + consented home.” |
| “AI is changing hiring.” | “Until apply-spam is `strong`, do not market ‘we kill AI cover letters’; still treat cover letters as low-signal in MVP (non-goal: letter generator).” |
| “Salary is important.” | “If CH ranges stay unpublished, company salary is an **enrichment / unknown** field, not a guaranteed filter — do not promise ‘always match on pay.’” |

## 7. Method

1. Open T1-Q20, Q5, Q8–Q9, Q11, Q14–Q16, Q18.
2. Slot each fact into T2-A…F. One fact can support only one card (or split sentences).
3. Write the three so-whats + must-not-claim. If you cannot write a product sentence, the fact is decorative — keep the card as `unknown`.
4. New URL only when T1 is empty for that theme. Log it in [SOURCES.md](../SOURCES.md).
