## Learn (orientation)

### What this phase is

Turn the vision into a **versioned product**: what ships first (MVP), what waits (V2/V3), which screens exist, how journeys work — then design those screens in Figma under the locked brand. Start from seeded [PRODUCT-CONCEPT.md](PRODUCT-CONCEPT.md) and [MVP-SCREEN-INVENTORY.md](MVP-SCREEN-INVENTORY.md). Decide keep / cut / add / rename / split — do not invent a second product from scratch.

### MVP vs V2 vs V3

| Version | Job | Rule of thumb |
| --- | --- | --- |
| **MVP** | Prove the **core match loop** with beachhead liquidity | If you cut it, matching does not work end-to-end |
| **V2** | Retention + trust depth | Improves quality after the loop works |
| **V3** | Scale + intelligence | Needs MVP+V2 learning — roadmap at Gate 4 |

Every feature belongs in **exactly one** version.

### Key terms

| Term | Meaning in plain language | Why it matters here |
| --- | --- | --- |
| **Journey** | Step-by-step path to value | Screens must cover the path |
| **Non-goal** | Something you will *not* build soon | Stops ATS-sized scope creep |
| **Screen inventory** | Table of frames: purpose, actions, data, states | Audit Figma completeness |
| **Scope checkpoint** | Daniel locks MVP/V2/V3 lists (Week 7) | Expanding later needs a new decision |
| **Annotation standard** | Purpose, actions, data, states, nav per frame | Gate 4: implementable without a workshop |
| **Bootstrap forward** | Pre-qualified candidates against ingested listings | Core GTM + MVP feature |
| **Indicator vs guarantee** | Match score suggests fit; does not promise a hire | Must appear in copy and states |

### Common mistakes

- Starting Figma in Week 7 before scope locks  
- Stuffing V2/V3 into MVP “just in case”  
- Designing a full employer ATS  
- Silent deletes of inventory rows  
- Figma without empty/loading/error states  
- Lists that disagree with VERSION-MAP  
- Treating V3 as build-blocking at Gate 4
