## Why this exists

The **scope checkpoint** (Week 7) locks MVP/V2/V3 feature lists. Every seeded feature should land in exactly one version — or be cut — with a short rationale. Expanding later needs a new decision-log entry.

---

## Our guideline

- **Exactly one version per feature.** “Nice for later” goes in V2 or V3 with a reason, or gets cut — no dumping ground.
- **Resist MVP stuffing.** Stuffing V2/V3 into MVP “just in case” is the main failure mode.
- **New features need a home.** Add only if you can name which journey step and version it serves — else cut.
- **Keep VERSION-MAP in sync.** [VERSION-MAP.md](../VERSION-MAP.md) must match your lists; note conflicts you resolved.
- **Smallest complete loop.** Seeker match list → company Top-X → mutual interview interest — defend the minimal set.

Mark keep/cut/move in the concept file itself — that *is* useful work, not a worksheet form.
