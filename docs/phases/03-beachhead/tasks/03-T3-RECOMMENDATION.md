## Why this exists

Daniel needs one clear proposed wedge — **niche × geography** in a sentence — plus written reasons you are *not* recommending the other scored options. Hidden runner-ups look like you ignored alternatives. This is a **proposal**. You do not lock Gate 1; only Daniel writes the decision log.

---

## Our guideline

- **One sentence recommendation.** Niche × geography — clear enough to paste into the decision log if Daniel approves.
- **Tie “why this” to T1 + T2.** Scorecard scores and liquidity facts — not a new story invented here.
- **Reject runners-up honestly.** **Runner-up rejection** = written reason you are not recommending that option — not a smear.
- **Surface risks.** Hide risks of the recommended option and the pack fails.
- **Do not write as approved.** Status stays pending Daniel until he locks the decision log.

Status quo from Phase 02 (portals, agencies, ATS) belongs in “why this wedge” vs “why not that.”

## What we're doing now

**Goal:** Write the proposed beachhead in one sentence, justify it from the scorecard and liquidity work, and reject each runner-up with evidence pointers and lock-in risks.

Example questions — decision-facing prose, not a new research sprint.

**Recommendation**

- Recommendation in one sentence: niche × geography?
- Why this wedge wins on the scorecard (short bullets, each tied to evidence or labeled **inference**)?

**Runner-ups and risks**

- For each runner-up: reject reason + pointer to evidence?
- Top risks if we lock the recommendation (product, liquidity, sales, compliance)?
- What would make you switch recommendation before Gate 1?

**Start here**

1. Write the one-sentence recommendation from the T1 leader (or explain a change).  
2. Tie “why this” to scorecard + liquidity, not a new story.  
3. Reject each runner-up with a pointer.  
4. List lock-in risks and a switch condition.  
5. Link [BEACHHEAD-RECOMMENDATION.md](../BEACHHEAD-RECOMMENDATION.md) (or notes) from the worksheet.
